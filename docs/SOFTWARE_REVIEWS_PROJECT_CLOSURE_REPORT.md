## 5. LESSONS LEARNED

### What Worked Exceptionally Well

1. **Strict READ-ONLY Auditing:** Enforcing read-only execution during Stage 1 and Stage 4 prevented accidental content degradation and ensured objective evaluation.
2. **Schema Blueprinting:** Establishing clear YAML schema definitions and component guidelines early eliminated build friction during Stage 3 implementation.
3. **Protected Content Register:** Locking high-value technical analysis sections (such as 1Password's Secret Key or Bitwarden's Argon2id breakdown) guaranteed that E-E-A-T authority remains preserved over long-term maintenance cycles.

### Key Challenges & Solutions

1. **Unquoted Frontmatter Strings:** Articles using `category: software-reviews` instead of single-quoted `'software-reviews'` caused preliminary filter mismatches.
   - _Solution:_ Normalizing all frontmatter strings to single quotes resolved counting discrepancies permanently.
2. **Internal Link Slug Divergence:** Historical links occasionally used absolute URLs or missing leading slashes.
   - _Solution:_ Enforced strict relative slug formatting (`/blog/[slug]`) during Stage 3.

### Recommendations for Future Clusters

1. Execute Step-1 inventory regex scans using both quoted and unquoted category matchers to establish the authoritative baseline on day one.
2. Mandate Contentlayer build validation after every safe patch batch.
